# 外部 Agent 穿搭制作 SOP

默认每天一个上海时区发布批次，交付一套生动九宫格和 `pieces` 中每件单品的独立页面。任务可指定套数或只做写真。先验收写真，再制作单品。仓库协作见 [AGENTS.md](../AGENTS.md)，清单、API 与代码位置见[内容发布](content-publishing-plan.md)。

## 1. 选模特与选题

1. 检查工作区、分支、远程和目标批次，保留无关改动。运行 `node scripts/resolve-model.mjs '男模特'`，参数可用登记编号、显示名或角色词，省略时选 `female-01`。脚本返回 `model_id`、`name`、`sop` 和 `reference`。打开返回的 SOP 与登记参考，核对 SHA-256。多套可逐套解析，选择词冲突或无法匹配时先确认。 [模特清单](../content/models.json) · [男模专用 SOP](male-outfit-sop.md)
2. 以 `Asia/Shanghai` 确定发布日期。对照最近至少七个批次和同模特内容，检查主题、地区、叠穿、配色、动作与情绪。任务指定地区时优先核验该地。
3. 先检索近期七天的穿搭和当地活动信号，来源不足时扩到三十天并标出范围。提出至少三个候选，用两个独立的具体原始来源支持最终主题。记录原链接、标题、作者或机构、发布日期、访问时间和概括。原帖、官方活动或原创报道可作为来源。同一内容的转载按一个来源计，无法核实的热度、榜单与互动数省略。
4. 核对当地气象机构或可靠预报的城市、适用日期、查询时间、最高与最低温、降水和风力。以温差、步行强度和室内外动线决定叠穿及鞋履，分开记录天气事实和搭配推断。改用可靠来源仍无法确认时，暂停依赖实时天气的选题。
5. 有私有移交包时，在仓库外阅读交接说明及生动模板，打开实际使用的参考图并记录版本。从已验收的基础生动写真挑选类似场景或材质样本，只用于摄影和排版对照。保留候选取舍、完整调研与输入证据为私有制作记录。

## 2. 写脚本并生成

固定模特、衣装、地点、场景光线和主情绪。衣装逐件写颜色、材质观感、版型、长度、纹理、叠穿次序、扣合状态、鞋包和配饰。逐套重写九镜头微故事，为每格安排表情、动作、景别、完整鞋履与观者互动，含至少一个适合现场的自然动态瞬间。

直接按生动脚本生成九宫格，实际附入登记模特参考。复刻既有服装时可附已确认的衣装图，并标注它约束的可见结构。使用中性身份表述，例如“保持所附模特参考的五官、发型发色、肤色、体态和身体比例，表情与动作随镜头变化”。基础参考衣装由目标衣装替换。

- 最终为竖版 `2:3`（常用 `1024 × 1536`），从左到右、从上到下排成 `3×3` 九个等大画面。两横两竖的细象牙色间隔连续贯通，沿等分边界对齐。以 1024 像素宽时约 4–8 像素为制作参考，高分辨率等比调整。
- 每格只出现同一模特，保持衣物件数、颜色、叠穿层次、鞋包和配饰一致。允许包随动作自然换位。肤质、手脚、重心、布料遮挡和光线自然，衣物完整且不透明。去除文字、编号、虚构标志、水印及画外肢体。
- 可先生成整图，或按同一脚本分格生成后等分拼接。以实际成片逐格验收，局部修正后重审整套身份、衣装与边界。成片与脚本出现差异时按实际画面更新镜头文案或修图。

## 3. 逐格验收与转码

| 项目 | 交付门槛 |
| --- | --- |
| 表情 | 至少 5 种可辨识表情，包含露齿笑和张口大笑。相似微笑合计为一种。 |
| 动作 | 至少 6 种不同动作。换站立朝向不单独计数。 |
| 鞋履 | 至少 3 格为双鞋完整可见的全身或中全身。 |
| 互动 | 至少 5 格通过目光或友好手势与观者互动。 |
| 画布 | 比例、九个等分边界、细象牙色间隔和逐格预览全部通过。相邻人物不串格，关键衣装和头部未被切断。 |
| 一致性 | 每格核对身份、完整穿搭、手足、身体比例及真实遮挡，记录失败项并修正。 |

在私有验收表记录每格实际表情、动作、景别、鞋履、互动与一致性结果。选择能清楚展示搭配的封面格，记录 `preview_panel`。

最终用原尺寸母本转为单帧有损 WebP，当前校验要求 RIFF 容器内的单个 VP8 块。可用 `cwebp -q 85 -m 6 -metadata none input.png -o output.webp`。打开转码结果核对边界和纹理，再计算尺寸、字节数与 SHA-256。完整提示词、私有参考、母本、过程及验收表留在仓库外。

## 4. 登记批次与关联单品

- 新批次按 [batch.schema.json](../content/batch.schema.json) 写入 `content/batches/<batch_id>.json`。批次 ID 以前缀 `publish_date` 开始，例如 `YYYY-MM-DD-01`。每天共用一个批次，所有当日穿搭写入 `looks`。检索时间用带时区时间，天气适用日期等于发布日期。可选 `published_at` 换算后必须属于同一上海日期，`cover_look_id` 指向批次内的穿搭，缺省取第一套。历史基线维持无发布日期。
- 按全局分配唯一整数 `id`。重试沿用分配好的 ID，修订资产使用新路径、资源 ID 和哈希。并行任务先协调编号、交接文件范围与清单合并人。新成片写 `edition: "v2"`，实填 `model_reference_sha256` 与按顺序编号 1–9 的 `shots`。图片存入 `assets/looks/YYYY-MM-DD/`，清单使用相对路径。
- 专用 SOP 或用户要求仅从模特页浏览时写 `model_only: true`。打开对应模特页、穿搭与关联单品核对入口。仅模特可索引批次沿用最近的全站主推，混合批次使用全站可索引的指定封面或第一套可索引穿搭。

### 单品页随穿搭一并交付

交给[单品制作 SOP](product-agent-sop.md)的输入包括 `look_id`、从 1 开始的 `piece_index`、当前写真 `reference_asset_id`、路径、SHA-256、模特编号，以及已批准参考与可见结构边界。各单品可独立分工，由同一负责人合并清单。补做已发布单品沿用原批次及当前验收成片。

## 5. 验证和交付

运行以下检查，并核实每件单品页面、图库与原写真预览。数据或图片变化需核对签名、尺寸、字节数与哈希，交互或布局变化需补充浏览器回归。

```sh
node scripts/check.mjs
node qa/regression-expressive.mjs
node scripts/build.mjs
node qa/regression-content.mjs
git diff --check
```

按项目授权提交推送，核对远程 SHA 和 CI。通过配置好的交付链路验证 API 与快照版本、首页封面或模特入口、该批次产品页和项目图片。CDN 凭据、配置与同步由服务端维护。 [部署说明](../deploy/README.md) · [开发站说明](../deploy/dev-README.md)

报告批次、穿搭和模特编号、地区与天气适用日期、选题来源、实际使用的参考及用途、成片路径、尺寸、字节数和 SHA-256。写明四项数量门槛、分隔及一致性验收结果，以及按 `pieces` 顺序的产品编号、图数、镜头、推演披露和缺项。分别列出源码推送、CI、服务端接收、页面及项目图片、CDN 的证据，无法观察的状态标为未核验。
