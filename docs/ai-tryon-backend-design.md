# 衣序：匿名 AI 试穿与第一方 Web Analytics 后台设计

- 设计日期：2026-11-11。
- 状态：设计稿，尚未实现；本文中的参数是建议初值，不是已测得的性能或费用。
- 目标站点：`https://www.8882088.xyz/`，保持 DNS 直连及现有自动 HTTPS。
- 设计基线：静态衣柜源码 `39df5ae6ef5e41cc8ee275def410ec151216ca04`。
- 本次设计不调用收费生图接口、不接收真实自拍、不部署新后台或新代理。

## 1. 问题与范围

用户正在某套服装、某个写真镜头中浏览，希望不用注册，直接拍照或从相册选一张自己的照片，得到“自己穿着这套衣服、出现在这个场景”的 AI 风格效果图。运营者需要看到访问、穿搭偏好、生成转化、失败原因、费用和容量，但不需要公众账号、用户中心或公开照片社区。

首期交付：

1. 穿搭详情中的“用我的照片试穿这套”入口。
2. 手机现拍、相册上传、上传预览和明确同意。
3. 本地单人人像可用性检查；未通过不能调用收费生图。
4. 自拍 + 当前场景单格参考 + 穿搭资料的 OpenAI 图像编辑。
5. 异步排队、进度状态、私有预览、WebP 下载、主动删除。
6. 最近最多 1,000 张生成成品的滚动存储和到期清理。
7. 第一方访问及业务统计、仅运营者可见的管理页面。
8. 独立、仅 loopback 监听的出站代理客户端，专供获准的 OpenAI 调用。

不做：公众注册/登录、手机号库、跨设备相册、支付计费、公开生成广场、批量生图、自由提示词、视频、模型训练、面部身份识别/特征库、精确尺码或合身度预测。若适用法规要求实名核验，应另行调整上线方案，不能用匿名 Cookie 代替。

## 2. 已核对的基础与设计约束

### 2.1 现有代码

- 前端为无依赖 HTML/CSS/JavaScript；已有 100 套服装、10 组分类、收藏、对比和详情弹窗。
- 收藏仍留在浏览器，不迁移成用户档案。
- “造型 / 生动”分别对应 `v1 / v2`；`catalog.js` 提供场景、单品、配色以及九个镜头的描述。
- **200 张源图均为 3×3 九宫格，不是独立镜头文件。** 现有 `setView` 使用 0 表示整张九宫格，1—9 表示单格。生图不能直接照搬整个九宫格，否则容易生成拼图、多人或混合镜头。
- 当前静态构建只复制 206 个公开文件；保持私有输入、生成结果、密钥、数据库及模型文件不进入静态输出。
- 旧站及 `file://` 打开方式仍可浏览；同源后台不可用时，试穿入口明确显示不可用，不把自拍静默转发到其他站点。

### 2.2 主机与网络

已读检查的部署主机为 2 核、约 1.70 GiB RAM；当时约 1.23 GiB 可用，磁盘约 33.93 GiB 可用。容量会变化，上线前必须重新测量，不能视为长期配额。

现有代理入站、Nginx 与证书自动续期均独立保留。新功能不重启或改写原代理入站，不修改全局代理、系统默认路由或站点的直连 DNS。部署阶段继续验证原服务 PID/重启计数、配置摘要和防火墙。

参考执行机现有客户端时确认其为 **Mihomo**，不是 sing-box 客户端：混合代理绑定 loopback、`allow-lan: false`，当前规则依赖规则集且最后为 `MATCH,DIRECT`。新客户端只借鉴可用出站节点和管理方式，**不原样复制整套规则，更不能把 CN001 自己的入站当作它的出站。**

## 3. 用户故事

1. 访客浏览某套衣服时，可以在详情中找到试穿入口，而不是去一个失去当前场景的独立首页。
2. 访客能确认本次使用的服装、版本和镜头，避免切换详情时生成错服装。
3. 在九宫格总览点击入口时，系统提示选一个镜头，默认预选可见的全身镜头；不会把九宫格当作单张效果图。
4. 手机访客可以分别选择“现在拍照”和“从相册选择”，不强制开启持续摄像头。
5. 访客可以先在本机预览照片、换一张或取消，确认前不上传。
6. 访客提交前能看到处理方、传输、用途、保存期限和 AI 误差提示，并主动同意。
7. 无人脸、多张脸、无法使用的模糊/过小人像会给出可理解的重拍建议，不触发生图消费。
8. 合格照片进入有上限的队列，页面显示真实阶段；刷新不会重复发起收费请求。
9. 生图期间切换穿搭、关闭弹窗或暂时离开页面，不会把原任务改成新场景。
10. 访客可以在同一匿名会话中查看和下载结果，但不能查看其他会话的自拍或成品。
11. 用户得到单张个人穿搭照片，不会得到参考模特的脸或整张九宫格。
12. 用户知道结果仅为 AI 风格参考，不承诺身份、体型、衣服细节或尺码完全准确。
13. 用户可以删除本地保留的结果；过期或因滚动上限淘汰时得到明确提示。
14. 不愿接受分析统计的访客仍可正常浏览；必要的任务计量与可选浏览分析分开。
15. 运营者能看到访问、热门服装/镜头、生成漏斗、成功率、等待时间、API 消费和剩余容量。
16. 运营者能关闭新任务、调整配额、检查未知调用和清理失败，但不需要浏览用户照片才能运营。
17. 代理或 OpenAI 不可用时，系统停止接单或给出暂不可用，不无限排队、不偷偷直连、不反复重发。
18. 服务重启后不会因恢复队列而重复计费，也不会因清理中断无限积累图片。

## 4. 推荐架构

采用 **现有静态前端 + 同源轻量 Python 后台 + SQLite + 一个图像 Worker**。首期不引入 Redis、PostgreSQL、GPU、本地生成大模型、Umami 全栈或容器编排。

```text
浏览器（现有衣柜 + 试穿面板）
       │ HTTPS，同源
       ▼
     Nginx
       ├── 公开静态衣柜及原有 200 张参考图
       └── /api/* → loopback 后台
                         ├── 匿名会话 / 同意 / 限额
                         ├── SQLite 任务、预算、结果目录与统计
                         └── 有界任务队列 → 单 Worker
                                              ├── 解码归一化 / 本地人像检查
                                              ├── 裁切场景参考 / 组装提示词
                                              ├── 专用 loopback Mihomo
                                              │        └── 合规获准的 OpenAI endpoint
                                              └── WebP 校验、标识、私有结果发布

运营后台：只监听 loopback，通过 SSH 转发使用；不面向公众开放。
```

- 后台拟用 FastAPI；Worker 使用同一代码库、独立进程与独立 systemd 单元。
- 拟使用项目专属、版本锁定的 Python 3.12 环境；不改系统 Python。实施时先核对依赖的当前支持矩阵、补丁版本、轮子可用性和许可证。
- SQLite WAL 保存任务、配额和统计；持久队列以数据库为准，不把内存队列当作唯一状态。
- 明确设置事务耐久性（首期 `synchronous=FULL`）和有界 WAL checkpoint；持久预算及发送状态不能依赖会丢失的缓冲，实际 fsync 时延纳入试点。
- 原子事务短小；图像解码、网络请求、文件删除不在长 SQLite 写事务中执行。
- 对外 Interface 为后台 HTTP 合约。内部只保留真实会变化的 Seam：图像提供方、图像检测/处理、文件存储。实现真实 Adapter；测试在这些位置替换外部收费依赖，不另造多层通用框架。

## 5. 入口与交互

### 5.1 页面位置

在现有穿搭详情的镜头选择器及场景说明之后，增加主按钮 **“用我的照片试穿这套”**，旁边写明“AI 生成效果，仅供风格参考”。首期复用详情弹窗，不重写前端框架；保留既有 `#look-N` 入口。

若需要可分享的固定“风格 page”，首期用带服装及镜头信息的深链接打开同一详情；不因此建立用户页面。未来真正独立路由可以复用相同任务合约。

试穿面板固定显示：LOOK 编号、造型/生动、镜头缩略图、镜头标题。打开时冻结这些值；后台也记录不可变的 catalog/reference/prompt 版本。切换其他穿搭不会修改已提交任务。

### 5.2 拍照与相册

- 两个独立按钮：“现在拍照”“从相册选择”。前者对应带 `capture="user"` 的文件输入，后者不设置 `capture`；浏览器行为和权限由设备决定，不承诺所有手机必然弹出相同 UI。
- 相机不可用、被拒绝或桌面端不支持时，仍提供文件选择。
- 本地预览使用临时 Blob URL，关闭后回收；不在 localStorage、分析事件或浏览器日志中保存照片/base64。
- 支持 JPEG、PNG、单帧 WebP；HEIC/HEIF 是移动端必要兼容项，必须先验证服务端受支持解码器及许可。暂不支持时明确提示转换，不能仅因前端 `accept` 设置就宣称支持。
- 不接收 SVG、HTML、PDF、GIF/动画、视频/Live Photo 附属视频或图片 URL。
- 建议原文件上限 12 MiB、解码像素上限 32 MP；正常化后最长边不超过 2048。前端可压缩减小上传，但后台仍独立执行全部限制，不相信客户端声称的 MIME、尺寸或检测结果。
- 原图清晰度或脸部像素不足时说明原因，不自动把低质照片送去反复付费试错。

### 5.3 用户同意

确认提交前，不预勾选同意；展示并记录同意版本和时间：

- 本人为已成年人，上传本人或具有明确授权的肖像；首期不面向未成年人。
- 为生成试穿效果，自拍将发送至明确披露的外部图像处理方；境外处理等适用事项单独告知和取得必要同意。
- 原图仅临时处理，成品非公开，最多保留最近 1,000 张且默认至多 24 小时，可能提前淘汰；请及时下载。
- AI 结果可能与本人面貌、体型和服装细节不一致，不是实际试衣或尺码建议。
- 删除站内照片不能等同于外部处理方即时删除；外部保留按已核实的实际政策说明。

仅靠“我已成年/已授权”的声明不能验证年龄或肖像权；不把人像检测包装成年龄核验、活体检测、身份认证或权属证明。必要的合法合规核验属于上线条件。

## 6. 图像处理与生成

### 6.1 本地检查先于收费生成

1. 先检查容量、接单开关、会话及 IP 速率、并发和预算预留，再签发短期上传许可。
2. 单文件流式接收，校验真实文件类型、总字节、像素数、帧数、解码超时；原文件名不用于服务器路径。
3. 修正 EXIF 方向、转标准颜色空间、去掉 GPS/设备等来源元数据、缩放到处理尺寸。
4. 在本机检测可用单人人像。首选候选为 OpenCV Zoo YuNet；固定具体模型文件与摘要，并验证 OpenCV/模型版本兼容，不追随未经测试的上游 `main`。[S5]
5. 建议采用“恰好一张可用脸、脸框足够大、曝光与清晰度基本合格”的门槛；无脸或多人拒绝并提示重拍。阈值由真实授权样本测试确定，不凭空宣称准确率。
6. 人脸检查只返回是否通过、错误类别及必要质量结果；不抽取身份 embedding、不做人脸检索、不推断年龄/种族等属性。检测通过不保证真人或本人，只是图像可用性检查。
7. 对输入和输出执行适用的内容安全检查。人脸检测不是 NSFW/违规内容审核；外部模型默认安全设置不降低。独立审核 Adapter 及适用政策需在试点时确定，若调用境外审核也须列入披露范围。
8. 通过后才进入可调用生成的任务状态；无效图像触发 **零次生图请求**。

### 6.2 九宫格与场景参考

- 浏览器只提交 `look_id`、`edition`、`shot_index` 等白名单标识，不能提交任意路径、参考 URL、模型名或自由提示词。
- `shot_index` 为 1—9。当前为九宫格总览（0）时，先要求确认一格，推荐该版本的全身镜头。
- 后台从受控 catalog 找到受控图片并裁切；基本边界按 `floor(i×width/3)`、`floor(j×height/3)` 分割，结合实图格线在测试后确定少量内缩，不能假定所有图片有相同像素宽度的边框。
- 输入 A：用户归一化自拍，是唯一身份来源。
- 输入 B：所选单格，提供场景、姿态、光线和当前风格。
- 若 B 是脸部近景看不清衣服，可额外提供同一服装、同一版本的一格全身参考 C，最多三张。**不把整张九宫格作为补充参考。**
- 同时读取公开的服装单品、材质、配色、场景、镜头构图和动作描述。catalog、参考文件摘要与提示词版本固定到任务，防止发布新版本后队列生成错内容。

### 6.3 OpenAI Interface 与模型

使用 **Image API 的图像编辑 Interface**，直接提交受控的图片字节，不上传到公开 URL，也不为本功能创建长期保留的 Files/会话资源。单次编辑更符合该任务，首期无需额外聊天模型或多轮 Responses 工作流。[S1]

截至本次查询，OpenAI 官方已提供 `gpt-image-2.6-sunburst` 的生成/编辑文档，并列出 2.6 Flare；不能把旧示例中的 `gpt-image-1` 当作当前默认。[S1][S2]

建议首轮试点：

| 配置 | 建议初值 |
|---|---|
| 模型 | 显式配置 `gpt-image-2.6-sunburst`，以该项目实际获准能力为前提 |
| 数量 | `n=1` |
| 尺寸 | `1024x1536` |
| 质量 | `medium`，不允许浏览器任意改成高价档 |
| 输出 | 请求 `webp`；实际格式必须重新解码检查 |
| 压缩 | 支持时设 `output_compression=85`，之后本地控制成品字节上限 |
| 安全 | 不降低默认审核设置 |
| 重试 | 关闭 SDK 默认自动重试，显式 `max_retries=0` |
| 超时 | 设定连接、读取与任务总期限，初值连接 10 秒、单次生成总期限 240 秒；试点再校准 |

官方 Python SDK 的默认重试及超时行为必须显式覆盖；网络超时不证明提供方没接收请求，不能把普通 HTTP 自动重试当作安全重试。[S6]

不套用旧模型专用的 `input_fidelity` 等参数；按所选模型的已验证能力清单发送参数。若只有其他模型可用，先进行版本化的显式配置和小样回归，不静默降级成另一收费模型或重新生成。官方以后提供日期快照时再验证、固定；目前不虚构 2.6 的日期快照。

### 6.4 提示词约束

采用固定、版本化模板，不开放自由 prompt：

- A 是唯一人物身份参考；B/C 中的人脸不是目标，不复制参考模特身份。
- 按 B 的环境、构图、动作、光线，把这套衣服穿在 A 所代表的人物上；C 只补充衣物结构。
- 保留自拍中的可见个人特征，不主动夸张改变体型或肤色；不得承诺模型绝对保持身份。
- 生成一张单人、单场景、照片风格的图，不生成九宫格、不生成多人、不复刻参考图上的边框。
- 衣服材质、颜色和单品来自受控 catalog；生成结果不是商品合身度保证。
- 可见 AI 标识由本地处理添加，不依赖模型准确生成指定文字。

## 7. 异步任务与匿名访问

### 7.1 没有公众账号，但有最小技术会话

- 采用高熵随机匿名会话 Cookie，`Secure`、`HttpOnly`、`SameSite`、主机限定、根路径；数据库保存不可反推的会话摘要，不记录明文 Cookie。
- 任务会话建议有效 7 天；不提供邮箱、密码、跨设备找回或用户资料。
- 清除 Cookie、换浏览器或切换设备会失去原任务的访问/删除能力；入口提前告知，残留照片仍按到期及全站滚动上限自动删除，不提供凭截图或 LOOK 编号找回。
- `job_id` 使用随机 ID；仅知道 ID 仍不能读取照片，所有状态、预览、下载、取消、删除都校验会话所有权。
- 状态和图片不公开缓存，使用 `Cache-Control: private, no-store`、合适的 Referrer/Robots 限制。Cookie/票据不得放进 query string、分析事件或 access log。
- 图片目录位于公开站点目录外，只经授权下载 Interface 或 Nginx `internal` 转发读取；禁止公开的 `/generated/*.webp` 图床。
- 不提供可永久转发的无鉴权分享链接；下载到设备的副本不受服务器删除控制。

### 7.2 推荐 HTTP 合约

| Interface | 作用 |
|---|---|
| `GET /api/bootstrap` | 获取可用开关、上传限制、配额说明、必要会话及 CSRF 凭据；响应不可缓存 |
| `POST /api/tryons` | 校验参数/同意/配额，创建短期有界上传许可；接收幂等键 |
| `POST /api/tryons/{id}/photo` | 所有者绑定的单文件上传与初步校验 |
| `GET /api/tryons/{id}` | 任务状态、真实阶段、过期时间和授权结果入口 |
| `GET /api/tryons/{id}/image` | 所有者的私有预览 |
| `GET /api/tryons/{id}/download` | 所有者的 WebP 附件下载 |
| `DELETE /api/tryons/{id}` | 删除成品或标记取消；多次执行幂等 |
| `POST /api/events` | 白名单、可丢弃且限流的第一方统计事件 |

幂等键在“会话 + 键”内唯一，关联规范化请求摘要；相同键同内容返回原任务，同键不同内容返回冲突，不创建第二次生成。它保证**本应用不重复调度**，不擅自声称 OpenAI 该 Interface 提供计费层的 exactly-once。

首次创建关联的是穿搭、镜头与同意参数；上传完成后再把唯一照片摘要绑定到任务。相同照片的上传重试返回现有状态，不重新排队；向同一任务换传另一张照片返回冲突，需要用户明确新建任务。

外部不属于该会话的任务统一返回不存在；所属会话的已清理任务可返回过期。错误体提供稳定错误码和可操作的重拍/稍后再试提示，不泄露上游响应体、Key 或私有路径。

### 7.3 状态与恢复

```text
reserved → uploading → validating → queued → generating → postprocessing → succeeded
                  └→ rejected         │             │              └→ failed
                        queued → expired/canceled    └→ unknown
                        generating → cancel_requested → canceled（完成后丢弃）
                        succeeded → expired/deleted
```

- 原始传输许可初值 60 秒；超时释放未使用槽位。
- 默认生成并发 **1**，等待队列最多 **3**，单个会话同时最多 1 个未完成任务；等待超 5 分钟则过期，不调用生图。
- 初始排队估时只能依据实测近期耗时；不伪造百分比。页面轮询采用退避，不维持长时间 Nginx 请求等待生图。
- Worker claim 使用持久状态、短租约和 heartbeat，生成前先持久记录“即将发送/可能已发送”。
- 任何处于可能已发送阶段的进程崩溃、连接中断或结果缺失，保守转 `unknown`；不把租约到期简单改回 queued。
- SDK、应用层与代理均不得自动重放可能已发送的生图 HTTP 请求；浏览器断开也不能触发再次发送。
- `unknown` 保持费用预留并进入运营待核对列表。页面说明结果未确认，不自动重试，不承诺未扣费。
- 只恢复明确尚未向提供方发送的任务。已取得输出但本地转码/发布失败，应在有限临时空间内恢复后处理，不再次调用模型。
- 用户取消待处理任务可停止并删除；生成中取消只能尽力停止/丢弃本地结果，不能承诺撤回已上传内容或消除上游计费。

## 8. 预算、防滥用与接入安全

### 8.1 建议初始限额

- 每匿名会话：每日最多 2 次生成尝试。
- 每来源 IP 的短期摘要：每日最多 10 次；另设请求级短时限速。
- 全站：每日最多 20 次实际生图尝试，运营者可调；不是 20 个成功结果。
- 一次外部调用都应占用尝试额度，包括费用尚不明的调用。无效上传不消耗生图次数，但消耗独立的上传/检测防滥用额度。
- 设置全站美元预算、单任务费用预留与紧急关闭开关；例如每日预算 10 美元只是建议，须由运营者确认，不自动消费。
- 同时设置月预算，任一必要预算未配置即默认关闭生成；日/月预留都要在同一准入事务内通过，不能每天归零而绕过月上限。
- 无账户体系无法可靠识别“同一个人”；清 Cookie、共享 NAT 或分布式 IP 均会影响限额。会话/IP 限流不是完整防机器人方案，不能因此取消全站硬上限。
- 首期不引入侵入式浏览器指纹。开放公众免费生图前，必须有后台验证的人机挑战；候选服务需先通过国内实际可达性和隐私评估。若挑战无法可靠落地，首批改为受控试用码灰度，而不是取消校验直接开放收费调用；两者均不是公众账号系统，也不能替代全站预算。

### 8.2 真正的费用控制

- OpenAI 使用独立 Project Key，仅 Worker 可读；前端、分析模块及普通日志拿不到 Key。
- 固定模型、数量、尺寸、输入张数和归一化尺寸、提示词长度，记录价格/参数版本。
- 在数据库事务中同时检查尝试数、`spent + reserved` 与剩余预算，先预留再接单，避免并发超额。
- 预留金额应基于当前计价和固定请求边界的可信最坏上界；未能验证上界前，不宣称美元级硬封顶已经成立。先以调用次数硬门禁、单 worker 和很小的获批试点控制风险。
- 成功返回后依据实际 `usage` 结算；缺失 usage 或不明调用保守保留预留，等待核对，不能先释放再补扣。
- 项目控制台的预算/告警是否强制阻断须单独验证；不能把告警阈值写成硬停机制。
- 单张费用包含自拍、场景/全身参考和文字输入，不只是输出图片。当前官方 2.6 Sunburst 标价为图像输入 8 美元/百万 token、图像输出 30 美元/百万 token，文字输入 5 美元/百万 token；这不是每张固定价格，实际成本必须用获准试点测量。[S3]
- 不在本次设计阶段使用现有助手凭据或未经授权的 Key 进行付费测试。
- 提供方响应也限制总字节，初值 32 MiB；不能在请求大小有界的同时允许无限响应占满 Worker 内存。

### 8.3 网络与上传约束

- 仅同源访问；不设置通配 CORS。写操作校验 Origin、CSRF 和必要 Fetch Metadata。
- 当前为直连站，Nginx 以实际对端 IP 覆盖传入的转发头；不能相信访客提交的 `X-Forwarded-For` 或 `CF-Connecting-IP` 做限流。
- API、Worker、Mihomo 与管理页面均不新增公网监听端口。Nginx 是唯一公开 Web 入口。
- 上传与解析都设总字节、像素、帧、时间、字段和文件数量限制，防止解压炸弹或慢速上传；队列和临时文件总量有硬界限。
- 流式上传时也要计数，不能因关闭 Nginx 请求缓冲就丢失总大小限制；所有 Nginx/框架临时目录纳入同一清理预算。
- 参考图片、OpenAI endpoint、存储路径完全由服务器控制，不接受任意 URL、路径或 Header，避免 SSRF 和路径穿越。

## 9. WebP 与磁盘生命周期

### 9.1 建议默认配置

| 项目 | 初值 |
|---|---|
| 全站生成成品数量 | `RESULT_MAX_COUNT=1000`，不是每会话 1000 张 |
| 单张最终 WebP 字节上限 | `2 MiB`，含标识元数据 |
| 成品最长保存时间 | `24 小时`；与数量滚动淘汰取先到者 |
| 所有临时输入/中间结果合计 | `128 MiB` |
| 原始上传 | 归一化成功即删；异常由定时与启动清理兜底 |
| 归一化自拍与生成中间文件 | 任务结束即删；硬期限初值 15 分钟，所有活跃任务也须有期限 |
| 整体私有数据预算 | 初值 `3 GiB`，包括成品、临时文件、数据库/WAL、日志及小型备份 |
| 主机磁盘安全余量 | 可用空间低于 `2 GiB` 停止接收新生图 |

1000 × 2 MiB 的成品上界约 **1.95 GiB**。这是配置上界，不是声称实际每张占用 2 MiB 或已经通过容量测试。现有 200 张公开参考图不属于用户生成成品配额。

- 以**生成完成顺序 FIFO**淘汰最旧成品，不依赖文件名、mtime 或最近访问时间。
- 成品只有一份；预览复用同一 WebP，不额外长期保留 PNG/JPEG/base64/缩略图副本，不把成品进入 Git 或常规备份。
- 即使 OpenAI 返回 WebP，也必须解码验证、应用标识、控制质量与大小后再发布。不信任文件扩展名。
- 压缩超限时只在本地有限重编码/降尺寸；失败不重调模型。
- 输入先去个人来源元数据；输出则必须保留/正确添加生成标识，不能在“去 EXIF”时一并删除 AI 来源标识。

### 9.2 1,000 张与崩溃一致性

SQLite 与文件系统不共享原子事务，不虚构“事务提交即可同时保证两者一致”。采用单发布者、持久发布意图及可重复恢复流程：

1. 完整候选成品先在有界的私有 staging 中完成验证与标识，不在已发布目录里放半个文件；staging 与成品在同一文件系统，写完校验并 `fsync` 后才能进入发布。
2. 发布时记录意图；达到上限则先把最旧结果逻辑标成过期并撤销下载权限，提交可恢复的 GC 记录。
3. 删除该过期成品的磁盘文件成功并同步必要目录后，才把候选原子移动到成品目录、同步目标目录并提交成功状态；删除失败则阻止新发布并报警，不继续累积文件。
4. 运行中的 staging 至多一个候选成品，独立计入 128 MiB 临时配额；已发布成品目录始终不得超过 1000 个成品文件。
5. 重启先对账发布意图、staging、成品目录及 GC，再恢复接单；无数据库引用的残留按安全规则清理，数据库指向缺失文件则转过期，不展示成功下载。
6. 清理幂等，测试崩溃在每个阶段发生的结果。恢复本地候选不产生第二次外部生成。

用户主动删除遵循相同的撤权与可恢复清理流程；拒绝新下载和物理删除的完成状态分别记录。不得承诺擦除用户已经下载的副本、浏览器内存或提供方数据。

## 10. 第一方 Analytics 与运营页面

### 10.1 统计内容

- 站点：PV、会话趋势、同意统计样本内的估算 UV、服装/分类/版本/镜头热度。
- 漏斗：详情打开 → 试穿入口 → 选择照片 → 合格人像 → 接单 → 生成成功 → 下载。
- 任务：检测拒绝原因、排队及生成耗时、失败/unknown 分类、超时、代理不可用次数。
- 成本/容量：实际调用次数、已确认费用、未决预留、结果数量和字节、临时空间、可用磁盘、清理失败。

事件白名单可包括 `page_view`、`look_open`、`shot_select`、`tryon_open`、`photo_selected`、`photo_validation_rejected`、`generation_started`、`generation_succeeded`、`generation_failed`、`result_downloaded`。服务器对生成与费用提供权威计数；不以客户端声称“成功/下载”作为结算依据。

“下载”应区分点击、获授权下载请求及服务器发送结果；即使 HTTP 成功，也不能证明用户已把文件保存到设备。

### 10.2 最小化与口径

- 自托管、第一方，不接入第三方跟踪脚本；Cloudflare DNS-only 不能自动提供完整站点访问统计。
- 可选浏览分析与必需的任务安全/成本计量分开，尊重适用的同意及退出机制。拒绝可选分析不阻断浏览；不偷偷用必要任务 Cookie 做长期追踪。
- 若启用 UV，使用已同意分析的每日轮换匿名标识，不构造 IP+UA 指纹，不把它叫实名人数或精确独立人数。
- 明细只保留受控事件名、LOOK/镜头等 ID、粗粒度设备类别及经白名单处理的来源域；不保存完整 URL/query、完整 Referer、原始 IP、完整 UA、输入文件名、照片、base64、面部属性或 prompt 内容。
- 限流所需 IP 使用短期密钥轮换摘要，并按限流期限到期清除；这属于最小化的假名化数据，不宣称绝对不可关联。
- 初值事件明细 30 天、每日无身份聚合 12 个月；设置明细数量、数据库/WAL、日志大小上限。法定安全日志要求另行审定，不把短期照片政策误当作全部日志政策。
- 访客统计可能被拦截、拒绝或重复，后台标明估算及样本范围。可选分析样本的前端漏斗与全站权威任务计数分栏显示，不能混成看似精确的全站转化率。
- 统计缓冲有界，超限可丢弃低优先级浏览事件，不能阻塞生成；预算与付费尝试记录不可随意丢弃。

### 10.3 运营权限

“不开发用户系统”不等于“公开管理后台”。首期管理界面只监听 loopback，通过 SSH 转发访问，无公众注册或运营者用户表。

页面提供汇总统计、队列、失败类别、费用预留、磁盘、全站开关及参数；默认**不提供运营者浏览自拍/成品的相册**。取消、清理、重试等操作也有确认与审计；`unknown` 不提供无提示的一键重生。

如以后需要手机直接外网管理，再独立增加管理员访问门禁；不因此引入公众账号体系，也不把管理接口直接放到公网裸奔。

## 11. CN001 专用 loopback 出站代理

计划建立独立的 Mihomo 客户端单元，借用现有配置中已获授权的合适出站节点，但不复制无关节点、订阅、控制口、规则集或凭据到公开仓库。

要求：

- `mixed-port` 拟用 7890，明确绑定 `127.0.0.1`，`allow-lan: false`；不绑定 `0.0.0.0` 或 `[::]`。
- 不开 TUN、不改默认路由，不在 Nginx 中代理公开这个端口。
- 不需要 Web 控制器时直接关闭；如确需控制器，只绑 loopback 并独立保护。
- 出站使用经核实的、**不是 CN001 本机入站**的节点；节点选择、账号及地区资格需符合提供方政策。
- 对 Image API 使用的准确域名走专用出站，其他连接默认拒绝；不是 `MATCH,DIRECT`。必要的代理节点解析/连接单独验证，避免规则阻断代理本身。
- 使用 multipart 字节及 base64 输出，首期不需要为临时图片 URL 开放任意外部域名。
- OpenAI Adapter 显式指定此代理、固定官方 HTTPS origin、验证 CA，并关闭环境代理继承和直连 fallback。代理失败即停用生成，不把人物照片静默走另一条链路。
- 后台其他模块不继承系统级 `HTTP_PROXY/HTTPS_PROXY`；静态页面、证书自动续期和管理访问不依赖新代理。
- 独立低权限运行；节点凭据只由客户端单元读取，OpenAI Key 只由 Worker 读取，均不写入命令行、Git、前端和日志。
- 验收检查真实监听地址与公网/内网不可连接，测试代理停机时生成失败关闭；验证既有网站、证书续期和原代理入站不受影响。

**代理只是传输工具，不改变 OpenAI 支持地区或账号资格。** 官方当前支持地区名单不包含中国大陆，且明确说明在名单以外访问或提供访问存在账户风险。部署前必须确认实际账号、运营主体、提供服务的地区与使用方式被允许；本设计不把海外代理视为绕过地区限制的授权。[S7]

## 12. 隐私、内容和上线条件

以下是待核实的上线条件，不是法律意见或已完成的合规结论：

1. **OpenAI 项目资格和地区**：核实合法可用的独立项目、图像模型权限、账单、限制及服务地区；代理连通不能替代此项。
2. **照片处理与跨境**：自拍是个人信息处理场景，须确定适用的告知/同意、敏感信息处理、个人信息保护影响评估及跨境路径或适用豁免；不能假定勾选一个框就完成所有手续。[S8]
3. **提供方保留**：OpenAI 官方数据控制表对 images edits 列出默认滥用监测保留，通常最长 30 天且有例外；ZDR/修改监测需要获批，不能向访客宣传默认零保留。站内删除只覆盖本机控制的数据。[S4]
4. **生成内容标识**：页面及下载文件均带清晰的“AI 生成 · 试穿效果”显式标识，并在最终 WebP 文件按适用规范记录生成属性、服务提供者与内容编号等隐式标识；转码后验证标识仍在。不能用页面上一行说明替代下载文件的标识，也不提供“去水印”功能。保留或正确建立衍生来源信息，不伪造上游有效签名。[S9]
5. **深度合成/生成式服务要求**：网站 ICP 备案不自动等于新增 AI 功能已完成所有适用手续；需核实内容审核、实名核验、算法备案/安全评估等适用义务。规定中有使用者身份认证等要求，“无注册账号”不能成为规避依据。[S10]
6. **无公开发布**：首期只有私有预览与本人下载，不建设生成广场、公开分享或人像检索；这减小产品范围，但不是自动免除前述义务的法律结论。

若资格、合规或所需核验与当前匿名范围冲突，保留静态衣柜和关闭的试穿入口，先进行允许范围内的开发/验证；与运营者明确调整范围后才开放公众真实生图，不静默改用其他提供方。

## 13. 数据模型与版本

建议保持少量表，避免通用用户平台：

- 匿名会话：会话摘要、必要有效期及同意记录；非用户资料表。
- 任务：LOOK/版本/镜头、catalog 与参考摘要、prompt/model/config 版本、owner、幂等摘要、状态、时限与稳定错误码。
- 调用尝试：预发送记录、上游 request ID（若取得）、usage、实际/预留费用、是否结果不明；不存照片或完整请求体。
- 结果：私有对象 ID、完成序号、字节、SHA-256、过期和物理清理状态；不由访客提供路径。
- 预算/配额：按明确的日界线（建议站点 UTC+8）记录已花费、预留、未决和尝试数；短期请求限流另计。
- 统计事件和每日聚合：按前述最小字段及期限保存，财务/任务事件使用幂等去重。
- 发布与 GC 意图：支持文件与数据库对账、失败恢复，不能只靠启动时“数一数文件”。

备份仅覆盖必要的配置与最小化元数据，设保留和容量上限；不备份个人照片或外部 Key。恢复数据库后必须先对账文件、预算和未决调用，不直接重放生图任务。

## 14. 测试与验收

测试优先跨同一个后台 HTTP Interface，使用临时 SQLite/私有目录与可控的提供方 Adapter。测试替身是确定性测试工具，不能把其输出说成真实 OpenAI 效果。

### 14.1 公开合约与隐私

- 手机/桌面相机权限允许、拒绝、不支持；相册、HEIC 支持与不支持分支；键盘/焦点、320/390 宽度布局、关闭与刷新行为。
- 错误 MIME、截断、炸弹像素、动画、多文件、超长字段、慢速上传、无脸/多人/模糊等均拒绝，生图 Adapter 调用计数为 0。
- 参考裁切对照真实九宫格，覆盖 1—9、两版与总览 0；不跨 LOOK、不多裁一列、不包含整张拼图。
- 不同会话不能读/删/下载对方结果；随机 ID 不是授权，内部文件路径不能直接访问。
- 同意未给、过期、Origin/CSRF 伪造、转发头伪造均正确拒绝。
- 访问日志、异常、统计、浏览器存储、公开构建及备份中没有原图、base64、Cookie、Key、来源元数据或真实文件名。

### 14.2 计费和故障

- 重复提交、重复上传、前端刷新、请求超时、worker 崩溃、租约到期、服务重启均不产生第二次不明收费调用。
- 在“未发送”和“可能已发送”的交界注入故障，后者必须进入 `unknown` 而非自动回队列。
- 多请求竞争最后预算/队列槽，验证只有允许数量进入；预留不能并发透支。
- 代理关闭或上游拒绝时失败关闭、不直连，不把非 200 响应当作图片。
- 对已成功取得、但编码/保存失败的输出只恢复后处理，不重新生图。

### 14.3 容量与一致性

- 1001 次确定性成品发布后，仅保留最新 1000 个已发布成品，最旧结果无法下载，原有 200 张参考图完全不变。
- 覆盖删除失败、磁盘满、移动/写入失败、数据库锁、每个发布/GC 阶段崩溃，重启后目录/数据库可恢复对账且不超限。
- 真实测量 upload、解码、检测、编码、API 等待、SQLite、代理的 RSS、CPU、磁盘增长与日志增长；不要把 `systemd active` 当成可服务。
- 建议起始资源预算：API 128 MiB、Worker 768 MiB、轻量代理 128 MiB 的进程内存上限候选，另保留主机与现有服务余量；必须用实际峰值修订，不能未经测试宣称满足。
- 减少图像/BLAS/OpenCV 内部线程，单图处理并发 1；触及内存或队列边界时拒绝/背压，不增加无界 worker。

### 14.4 获批真实小样

在取得 Key、地区/合规条件与明确试点预算之后，用授权的真实成年人照片进行小样：不同光照、姿态、发型/眼镜、肤色、正侧脸；不从陌生人相册抓取样本。

记录通过率、误拒率、身份/服装/场景保持的人工评价、P50/P95 时延、usage、费用与成品字节，确认可接受再开放。不得用合成测试替身的“成功率”替代真实生图或人像检测测量。效果不达标时调整明确版本或停止，不自动消耗更多次数刷到满意。

32 MP 的解码上限是为兼容常见手机照片的候选值，不是已证明能在本机安全处理的能力；若实测峰值不满足余量，应增加明确的前端降采样/转换指引并降低服务端上限，不能靠放宽内存约束或多 worker 掩盖失败。

## 15. 分阶段实施

### A. 第一方统计与后台骨架

- 明确并更新原 `AGENTS.md` 的“无分析/无上传”规则：本次新授权仅对已设计的第一方最小化统计和主动同意的自拍处理建立例外；收藏仍本地。
- 建立版本锁定、私有数据目录、SQLite 迁移、loopback 后台、健康检查、接单开关、管理页与统计白名单。
- 初始生图默认关闭；静态衣柜与 HTTPS 持续可用。

### B. 上传、检测、任务与配额

- 做前端入口、拍照/相册和同意；实现上传限制、本地人像检测、任务所有权、幂等、预算预留、清理和故障恢复。
- 用确定性 Adapter 完成自动验收，不把替身对公众展示为真实 AI 结果。

### C. 代理及真实提供方试点

- 独立部署 loopback Mihomo，核实出站、不暴露端口、不影响原服务。
- 配置独立 Key、实际可用模型、审核及标识；只有在资格/合规/预算获准后才执行小样付费调用。
- 测量资源与质量，复核上限、失败关闭、隐私披露。

### D. 受控开放

- 先小额度灰度，检查端到端移动端拍照/上传/下载，再调整日配额。
- 运营者可随时关闭新生成，不影响浏览、已有结果下载或必要清理。
- 回滚只关闭入口/接单并停止新调用，保留必要清理与未决费用记录；不通过重放队列或恢复照片备份“回滚”。

## 16. 实施前仍需确认的事项

1. 合规允许的 OpenAI 独立 Project、实际模型权限及服务地区；不是要求把 Key 发在聊天或公开仓库。
2. 真实试点及开放后的日/月预算，是否采用上述每日 20 次 / 会话 2 次的初始门槛，以及人机挑战或受控试用码的灰度方式。
3. 适用的隐私、肖像授权、跨境、内容标识、审核及身份核验结论；若需要改变匿名范围，先明确决定。

其余工程选型按本文建议即可推进，无需为了管理游客再开发一套账号系统。
