# 外部 Agent 单品图组与产品页交付 SOP

本 SOP 与[热点穿搭 SOP](external-agent-sop.md)组成同一内容工作流的两个独立阶段：先验收穿搭生动九宫格，再按任务授权制作其中单品的独立图组。可以单独接收已发布穿搭开展单品任务，不重新选热点、重生穿搭或占用新的每日穿搭批次。项目规则见 [AGENTS.md](../AGENTS.md)，内容与主题合同见[开发说明](../DEVELOPMENT.md#单品主题与内容合同)。

单品页面由 `content/products.json` 与最终 `assets/products/**/*.webp` 更新，格式见 [content/products.schema.json](../content/products.schema.json)。先验收穿搭成片，再依照其实际衣装、私有造型参考及已确认描述制作独立产品图。逐件核对颜色、轮廓、领口、拼缝、鞋跟等可见结构；未展示部位保持克制并明确属于设计演绎。材质文字只表达设计效果，真实品牌、成分、尺码、价格和货源须另有依据。

独立产品的基础陈列图约为竖版 4:5，整件完整入镜，使用克制中性背景，无人物、文字、品牌和水印；图组中的穿着参考另按模特与单品共同约束验收。3×3 与 2:3 规范继续适用于穿搭写真。最终图转换 WebP，填写真实尺寸、字节数和 SHA-256。保留稳定单品编号，关联精确穿搭编号、单品序号和写真资源修订；复用前人工核对是否确为同一件设计。仅交付公开最终 WebP 与清单，完整提示词、原始生成图和造型中间稿不进入仓库或图床。

## 执行顺序与输入合同

1. **核对版本与授权。** 检查工作区、分支及远程，保留无关改动；读取本项目规则、两个 SOP 和现有单品清单。明确只制作单品，还是连同已经授权的穿搭任务一起交付。不要自行部署公共生产环境。
2. **锁定精确输入。** 记录 `look_id`、从 1 开始的 `piece_index`、原写真 `reference_asset_id`、文件路径及 SHA-256；打开该修订的完整九宫格和相关局部。检查登记模特参考与可用的私有造型中间稿，分别说明用途。当前单品关联只能引用该穿搭公开的精确生动写真修订，不能指向已被替换的旧图或私有中间稿。
3. **盘点再生成。** 按 `pieces` 顺序列出每件单品、已有 `product_id`、当前主图及附图、验收状态、复用范围与缺口。复用已验收资产，不因做一次整套测试就重生全部图片，不覆盖旧字节或改变既有收藏身份。
4. **建立参考证据表。** 按下方摄影标准，区分原图可见、已批准设计与未知部分。若无足够参考证明背面、内里、包内结构、鞋底、耳针或耳堵，优先省略；任务确需新设计时明确为设计推演，并按清单能力标识，不将其写成原款事实。
5. **按信息量写镜头单并分工。** 明确每张要回答的问题、品类结构、允许变化、参考范围与验收项。主图与完整角度单张生成；只有同一单品的关联细节适合双联合图。独立单品可并行，参考修订、命名分配和最终清单由统一负责人协调。
6. **生成、切分、人工验收。** 按下文流程制作并打开实际图像，逐图检查一致性；双联合图须先检测白边并安全切分，再分别验收。记录少图或省略镜头的理由，不用相近裁切凑数。
7. **结构化交付。** 仅将验收后的最终 WebP、图片元数据、纯文本与精确穿着关联更新到项目；主题渲染交给框架。完整提示词、参考证据、母本和切分记录保存在仓库外私有目录。
8. **统一验证与发布核验。** 合并各分工产出后校验全部清单、图片、API/快照及浏览器效果；按已有授权提交推送与交付 LAN，分别报告代码、CI、服务端、项目图片和 CDN 状态。

## 电商摄影图组标准（2026-11-13 调研后更新）

本节是衣序自有设计展示站的制作标准，不是 Amazon、淘宝或天猫的上架合规证明。2026-11-13 调研时，三位 agent 分别核验平台规范、摄影设计、工具与技能，并交叉评审；当时三张样板干净、轮廓清楚，但每件只有一个图片资产，网页的局部放大也复用了主图。该历史问题促成有信息分工的图组方案；当前已验收状态以清单与本次盘点为准，不重复生成已合格资产。

#### 1. 先写参考证据表

每件任务先记录以下三类信息，保存在私有制作记录中：原写真实际可见的结构；已登记 AI 单品母图中已经批准的设计；没有可靠参考的未知部位。清单当前批准的单品修订是本设计的视觉基线，不证明真实商品存在，也不证明原写真未展示的结构。完整色型锁定使用该修订单品母图，原写真只约束其中实际可见部分；尚无母图时先验收主图，再以此锁定后续镜头。

针织衫在第 102 套中被外套与裙腰遮住，不能从原写真验证完整衣长、后背和衣摆；长靴的鞋底与细缝也缺乏充分参考。裙装的腰头、前中缝、A 字轮廓与裙长较清晰，因此在 2026-11-13 优先用皮裙试制，现有验收图继续复用。需要真实成分、工艺、内里、扣件或背面结构时，必须补对应高质量参考；缺失时省略该镜头，或明确作为待批准的设计补充，不能编造为产品事实。

#### 2. 每件先规划四个角色

| 角色 | 回答的问题 | 拍摄与生成约定 |
| --- | --- | --- |
| 完整识别图 | 单品是什么，整体颜色与轮廓如何 | 全件入镜，适度留白，明确承托或物理合理的呈现；依据材质控制阴影与高光。 |
| 结构说明图 | 哪个已知结构值得看清 | 围绕领口、腰头、中缝、鞋头或鞋跟独立取景，保留母图结构，不添加未知五金或接缝。 |
| 肌理与形态图 | 面料或表面如何接光、垂坠 | 使用侧向柔光与自然折面展示设计效果；新生成纹理属于 AI 设计演绎，不能当真实材质的检测或工艺证据。 |
| 穿着上下文 | 与模特、其他单品的比例关系如何 | 优先引用已验收写真中的对应画面；新生成穿着图须同时参考登记模特照片、单品母图与原穿搭，重新验收身份与服装。 |

每张镜头必须写明新增信息。裁切旧图可标为“主图局部”，裁切原九宫格可标为“原写真穿着参考”；两者不能标成新取景或高分辨率微距。一个四图组可以诚实复用一张原写真，但前三张不能只是相同主图换裁切、换背景。

后三类配方用于此次六件单品测试；候选镜头需实际打开原图检查后才可登记。简单圆耳钉可只交付完整主图与一张有信息增量的近景，原写真另用关联展示，不为了凑 6–8 张创造耳堵、尺寸标尺或未知结构。肩带长短和耳钉大小只做原图比例一致性判断，不能写成未经测量的厘米或毫米。

针织避免过度磨皮和粗大编织纹；皮裙避免漆皮般镜面高光与无重力的均匀悬浮影；深色长靴保留鞋头、鞋跟与鞋底边缘的层次，不用整体提亮改变颜色。道具只承担支撑或场景解释，不遮住产品，不让三件都复制相同居中悬浮构图。

#### 4. 分开执行两条流程

**基底场景编辑**：把已批准母图明确标为编辑目标，限定背景、留白、承托、光照或阴影的修改范围。输出仍须与母图并排核对，不能因工具声称保留产品就跳过验收。此路线不能制造未见结构或新视角。

**参考约束的新取景**：把母图、原写真及必要局部参考分别注明用途，逐张生成指定镜头。它会重新解释像素，须重点核对色型、领口、罗纹、拼缝、腰头、鞋头和鞋跟。每轮只调整一个主要问题；不能把服饰轮廓的漂移当成摄影风格变化。

通用任务单应包含：目标渠道、镜头角色、要回答的视觉问题、各参考的用途与可见范围、不可变结构、构图、光线与支撑、允许变化、未知部位处理、输出标签、逐项验收结果。通用提示词可用占位结构公开；当次填好的完整提示词及生成母本继续私有保存。

#### 5. 实际验收

建议内部评分：单品一致性 35 分，光线与材质表达 20 分，镜头信息增量 15 分，物理与空间可信度 15 分，清晰度与交付 10 分，衣序视觉统一 5 分。总分至少 85，且一致性至少 30/35；这是本项目的设计验收建议，不是平台或工具认证。

逐图与母图并排检查颜色、轮廓、结构和比例，按 100% 实际像素查看边缘、接缝、重复纹理和压缩块。出现明显改色改型、错误接缝、未知结构冒充既有事实、严重漂浮、穿插或伪造品牌时直接退回，总分不能抵消。不把插值锐化当作新增真实细节，不用生成纹理证明材质成分。

#### 6. 当前清单与交付边界

`content/products.json` 使用 `asset` 登记完整主图，可选 `gallery` 登记最多八张附图；每项使用 `title`、`caption`、`asset`，资源格式与主图一致。可选 `role` 为全貌 `view` 或细节 `detail`（默认）；`design_study` 为严格布尔值，设计推演必须为 true，并在 `caption` 中明确缺少参考的部位。Node/Python 导入、静态导出和资源 API 均校验并提供画廊。前端按角色显示多角度和细节，保留整体顺序供缩略图与大图浏览。第 102 套棕裙与长靴可作为交付样板；长靴背面是已明确标识的设计推演，不证明原写真未展示的结构。原写真通过 `appearances` 保留穿着上下文。新一轮仍先私有试制并验收，不把待审草稿放入公开目录。

单品页面由内置主题统一渲染。内容 agent 只交付最终 WebP、清单与纯文本，不为每件产品编写 HTML/CSS，不向文案嵌入标签、脚本或主题 URL。可选 `presentation` 选择 `{"theme":"editorial","preset":"warm-paper"}`（留白叙事）或 `{"theme":"studio","preset":"neutral-white"}`（图库优先）；省略时使用 Editorial。可选 `copy` 只填写 `hero_title`、`views_title`、`details_title`、`worn_title`、`related_title`，每项 1—200 字符非空白文本，缺省标题由框架提供。完整合同与同内容双主题预览方式见 [开发说明](../DEVELOPMENT.md#单品主题与内容合同)。未知安全主题回退 Editorial，不能借主题隐藏设计推演披露、穿着参考或替换资源规则。

先根据产品形态、结构复杂度和参考覆盖规划完整图库，不按品类套用固定镜头数量；复杂单品可将有信息增量的 6–8 张作为常见目标，简单单品可少图，并记录为何足以说明设计；没有最低凑图数。主视觉与完整角度独立生成；同一单品的关联细节可每批双联生成，再检测连续白边、等宽与安全边界后切分。逐张检查原生尺寸与构图，必要时只裁切为约 4:5，不通过放大冒充高清。白边有轻微抗锯齿时可容忍有限边界噪声，无法可靠定位时拒绝自动切分。只交付最终单张 WebP，整张母本、填好的提示词及过程记录继续私有保存。

不把主图裁切冒充独立近景，不把生成细节写成实物工艺证明。原写真穿着参考使用精确 `appearances`，不重复生成模特画面。沿用最终 WebP、本地保存、SHA-256、CDN 未就绪时使用项目 URL 的交付方式。新图使用新修订和资源 ID，不覆盖已发布 r1 字节。

访问日期为 2026-11-13；平台规则和工具能力在实际执行时复核。

- [amazon-product-photography 技能源码](https://github.com/nexscope-ai/Amazon-Skills/blob/main/amazon-product-photography/SKILL.md)：可参考逐图规划和输入证据分层，但附带服务推广指令，不整体安装。其他高安装量同名技能存在额外服务登录、通用提示词或来源不可核验等问题，不以安装量代替内容审查。

## 双联合图与安全切分执行

- 一张完整主视觉或一个完整角度独立生成，以免切分压缩关键轮廓、肩带或长袖的可用像素。新生成镜头必须使用已验收单品母图与原写真作为约束；各输入分别注明是身份、色型、比例还是已见结构参考。
- 同一单品、同一批准设计的两个相关局部可一次生成双联，例如外套翻领/袖口、包身轮廓/肩带局部。提示词要求两个等大独立画面，画面之间为贯穿全高的纯白或近白干净间隔，两侧主体与分隔均保持安全留白，不交叉、不带字。不同单品不混入同一双联母本。
- 提示词要求白边不等于检测通过。先用代码检查像素：候选分隔应位于预期中线附近，是连续、近白、低变化的带状区域，覆盖全高；检查左右可用宽度、主体边缘距离及输出构图。记录检测阈值、白边坐标、裁切框与是否留有足够原生像素。白边轻微抗锯齿可容忍有限噪声，但不能将产品高光、细肩带或大块白底误判为分隔。
- 按检出的安全带去除整段分隔，再单独检查两侧；只做约 4:5 的安全裁切，不拉伸、不放大，不为裁齐比例切掉主体。找不到可靠贯穿白边、主体越界、两侧图尺寸不足或关键信息被裁掉时，拒绝自动切分，重新生成或改为独立镜头。
- 打开完整母本与每个切分结果，核对无白缝残留、无相邻画面污染、无裁断、无重复镜头，且服装/配饰的一致性与细节通过实际验收。单张失败可重做该镜头，不把失败半图与合格半图一起交付。母本、检测和完整提示词继续私有保存，只输出最终单张 WebP。

## 清单、主题与私有制作记录

`content/products.json` 是唯一单品内容入口，产品采用稳定 `product_id`；主图使用 `asset`，附图 `gallery` 最多八项。每张附图写独立的 `title`、`caption`、`asset`、语义 `role`（`view` 或 `detail`）；缺省 `role` 按细节处理。`design_study` 必须是布尔值，缺少结构参考的设计推演附图为 true，并在说明中明确参考边界。主图没有独立的 `design_study` 字段，因此主图优先采用证据充分的完整识别角度；主图本身含设计补充时在产品描述与说明中披露，不擅自添加 schema 外字段，也不声称原图证明了它。

`appearances` 精确记录 `look_id`、`piece_index`、`reference_asset_id`、`shot_index`。候选镜头编号只用于查找，实际打开确认可见性后再登记；耳部被头发遮挡不能靠镜头文案宣称耳钉已可见。复用原写真作为穿着上下文，不重复生成模特，不将裁出的低分辨率局部命名为新生成微距。

`presentation` 选择内置主题，`copy` 只提供章节纯文本；不可注入 HTML/CSS、脚本、远程主题地址或自行编写产品页。框架负责排列画廊、未知配置回退、设计推演标签、收藏和项目图回源。所有单品使用相同合同，不按类别虚构特定字段；详细默认与验证规则见[单品主题与内容合同](../DEVELOPMENT.md#单品主题与内容合同)。

每个验收图保存原生尺寸、压缩前后对比、最终 WebP 字节数及 SHA-256；新修订使用新的路径与资源 ID，不能覆盖已发布资产。私有制作记录应包含精确参考哈希、证据表、各输入用途、完整提示词、原始生成母本、切分参数和逐图验收结果。公开项目只保留最终 WebP 与必要内容元数据，不包含 ZIP、完整提示词、PNG 母本、原始生成记录、用户私人图片或本机身份路径。

## 合并验收与统一交付

先检查整套六件是否与同一写真修订一致，逐件确认颜色、比例、结构、画廊角色、说明与穿着关联，再执行：

```sh
node scripts/check.mjs
node qa/regression-expressive.mjs
node scripts/build.mjs
node qa/regression-content.mjs
git diff --check
```

数据或图片变化必须核对文件签名、尺寸、字节数与哈希。涉及主题或交互变化时补浏览器回归；即使没有修改框架，也实际打开新增单品的桌面和手机页面，检查主图、每张附图、缩略图/放大、图像失败回源、推演披露、原写真关联与收藏。核对 API 与离线快照使用一致的内容版本，旧产品链接和收藏保持可用。

统一负责人审查并提交已验收产出，按项目授权推送后核对远程 SHA 与 CI。LAN 部署需要已有明确授权，并使用项目配置的受控交付命令；其他 agent 不自行重启服务或直接上传图床。交付后核对六件条目的 API、页面实际展示、主图及附图 URL/哈希、内容版本与服务端接收记录；若本次没有新增穿搭，首页仍保持最新发布批次的原封面，不通过单品任务改写穿搭发布日期。

报告分别列出：各单品复用/新增/省略的镜头与理由，精确关联、最终路径/尺寸/字节/SHA-256、验收结果、提交 SHA、CI、LAN 产品链接与服务端接收状态。CDN 单独核验；未配置或同步失败时继续使用项目图片 URL，不能因此重生图片或声称 CDN 已同步。未核验的项目如实记录，不能用源码存在或 CI 成功代替页面上线证据。

## 可直接交给单品 Agent 的任务指令

委派任务时填写以下通用任务单；它只约定输入、边界和验收，不替代当次私有完整生图提示词：

```text
目标：为 <look_id / 穿搭名称> 的 <piece_index / 单品名称> 制作独立图组。
参考修订：<reference_asset_id>；原图 <相对路径>；SHA-256 <实际哈希>。
已验收单品：<product_id 或尚无>；当前母图 <资源ID/修订 或先生成并验收主图>。
参考分工：<原写真可见结构>；<批准母图锁定色型>；<模特图仅在确需新穿着图时约束身份>。
已知与未知：<保留结构>；<不得推断的背面、内里、五金、耳针等>。
镜头清单：<每张角色 / 新增信息 / 构图 / 光线 / 原生尺寸目标>。
生成方式：<独立主图与全貌>；<适合双联的相关细节及分隔/安全边界要求>。
文件范围：<仅本单品的新资产路径与ID>；清单交接 <统一内容负责人>。
验收：<一致性与实际像素检查 / 白边检测与切分 / 推演披露 / 原写真可见性>。
交付：<最终WebP与元数据 / gallery role / appearances / presentation与copy建议>。
私有记录：<仓库外工作目录>，保存完整提示词、母本、参考证据和切分/验收记录。
完成报告：<复用/新增/省略及原因>，不自行提交、部署或直传图床，交统一负责人验收。
```

> 按 `docs/product-agent-sop.md` 为指定已验收穿搭制作独立单品图组。先读取清单与图片，锁定精确 look/piece/写真修订并盘点全部单品；复用已验收资产，建立可见结构、批准设计与未知部位的证据表。按品类和信息量设计镜头，不以 6–8 张为最低数量。主图和完整角度独立生成，同一单品的相关细节可双联生成，检测连续白边与安全边界后切分；拒绝不可靠切分，不放大假冒高清。检查颜色、形态、结构、物理合理性与图像质量；未知背面、内里、耳堵等省略或明确标为设计推演。最终交付约 4:5 的 WebP、真实哈希、纯文本、gallery 角色与精确 appearances，用 presentation/copy 交由内置框架渲染。完整提示词、母本、切分参数与参考证据保存在仓库外私有目录。独立单品按文件范围拆给 subagent，统一负责人合并验证；按已有授权交付 LAN，分别报告 Git/CI、服务端、项目图片和 CDN 的实际状态，不自行配置公共生产环境或图床。
