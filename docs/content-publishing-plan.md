## 1. 已确认的职责

外部 agent 搜索热点、地区与天气，使用登记模特创作穿搭，生成生动九宫格，转码为 WebP，并通过更新项目代码和公开资源交付内容。每日一个批次，默认一套穿搭一张九宫格；批次规模可由任务明确覆盖。服务端不承担每日选题、生图、后台录入穿搭或自动创作调度。

制作细节按移交要求采用两阶段参考：先以模特参考照片和精确衣装生成私有造型中间稿，再同时参考模特照片与造型图生成生动九宫格。人物使用中性表述，画面为竖版 2:3、3×3 等大画面及细象牙色间隔；逐套重新设计九镜头微故事，实际达到至少 5 种表情（含露齿笑与张口大笑）、6 种动作、3 格含完整鞋履的全身或中全身、5 格与观者互动。最终提示词、中间稿和生成母本私有保存，公开内容仍仅登记生动 `v2` WebP。详细参考分工与验收见 SOP，不能用未读取的原始模板名代替实际输入。

后台主要提供第一方访问分析、资源 API、用户穿搭与生成结果观察、系统模特预览，以及 CDN 同步进度和故障观察。配置好交付链路后，服务端接收内容版本并自动归档和同步公开资源。CDN 可用前直接使用项目图片的公开 URL；同步不阻塞已完成本地资源准备的内容展示。

首位模特为 `female-01`，使用仓库现有 `assets/model-bases/female-01.webp` 五视角参考。新内容仅 `v2` 生动版；历史 `v1` 造型版保留归档，但从公开网站的全部展示及公开内容索引中隐藏。历史编号和收藏对应关系继续保留。

## 2. 内容源与运行数据

项目中的版本化内容清单是穿搭与系统模特的内容源。数据库保存清单导入结果、资源投影、CDN 副本、同步任务、活动内容版本以及分析和用户数据。数据库中的导入内容是可重建的读取资料，后台不提供另一套与 Git 竞争的穿搭编辑来源。

当前内容结构为 `content/models.json`、`content/batches/YYYY-MM-DD-01.json` 和 `assets/looks/YYYY-MM-DD/*.webp`。首期沿用公开最终 WebP 随项目资源交付，服务端复制到独立持久化归档。资源规模扩大时可以改为有哈希的独立交付包，仍由版本化清单引用，不改变外部 agent 的内容管理职责。上述目录已接入校验、离线构建和服务端导入；批次格式见 `content/batch.schema.json`。

模特、穿搭、模特穿搭展示、图片资产、每日批次分别建模。同一服装可由不同模特展示，图片与镜头绑定具体展示及修订。沿用现有 1—100 编号，后续使用稳定的新编号；日期、分类和展示排序不是图片或穿搭的身份。`female-01` 与历史写真人物的关联需核对，不能直接把历史所有图片认定为该基础体。

数据库先复用现有 FastAPI/SQLite 基础，新增有版本的迁移与唯一约束。公开内容任务和私人试穿任务分别记录和处理；公开档案不受私人生成结果最近 1,000 张的滚动淘汰规则影响。

## 3. 公开与私有存储

| 数据 | 存储与访问 |
| --- | --- |
| 公开内容清单和最终穿搭 WebP | 随授权版本交付；最终 WebP 本地归档，受控公开目录提供项目图片 URL，明确标记公开的资源可同步 CDN |
| 系统模特参考图 | 按资产可见范围使用；仅供后台的参考资产不自动同步公共 CDN |
| 历史造型图片 | 保留本地归档及对应关系，不在公开内容索引出现，不默认列入新 CDN 同步范围 |
| 图床链接、远端标识和同步记录 | 服务端数据库维护；公开接口只返回已就绪资源的必要字段 |
| 访问事件、用户试穿任务及照片/成品、评估记录、会话、密钥 | 持久数据留在服务端私有存储，按原有权限与保留规则处理，不进入 Git、公开静态包或公共 CDN |
| 原始生成文件、实际完整提示词及完整调研过程 | 外部 agent 的私有工作区，不进入 Git 或公开同步清单 |

本次不扩展用户数据的采集范围，用户收藏继续沿用浏览器本地保存。已有照片试穿的外部生成处理仍遵循既有披露和主动同意。公共资源同步只遍历已验证清单中允许公开的资产，不递归扫描服务器目录。

## 4. 内容接收与增量同步

一个版本依次经历接收、清单验证、本地归档、项目图片 URL 验证、可见内容版本切换；CDN 同步和远端验证随后异步执行。用内容版本与资产哈希去重，归档目录独立于会被替换的代码发布目录。项目图片 URL 必须由受控公开目录提供，不能直接暴露归档根目录；新版本构建与部署不能清理仍被引用的历史公开图片。

同一任务重试复用相同标识；校验失败不进入同步，上传失败保留本地资产。已上传的资源先核对可访问性、真实 MIME、尺寸和适用的内容校验方式。平台若转换输出，必须明确记录远端变体及其元数据，不能将其冒充本地文件的相同哈希。

候选批次的必需资源全部在本地验证且项目图片 URL 就绪后，短事务切换活动内容版本并失效相关查询缓存。资源 API 此时返回项目图片 URL，不等待 CDN。项目资源不完整时继续保留旧版本，不发布缺图内容。CDN 中的每张图片验证完成后，独立切换该资产的优先链接；同步中、失败或未配置的图片继续使用项目 URL。数据库事务不覆盖外部上传，失败恢复依靠持久阶段记录，而非假设数据库与图床能做一次跨系统原子事务。

同步日志与内容版本可用于回滚。撤下内容时切回有效版本，不自动删除其他版本或图床原文件。数据库、归档资源及清单配套备份和恢复；历史源图片不因迁移而重新有损编码。

## 5. 可更换的图床接入

暂不绑定平台。已定义上传、读取验证和能力查询接口，并提供可替换的通用 HTTP PUT 接入，选定免费图床后再按其实际协议接入。平台能力明确包括是否支持幂等上传、按对象查询、删除、原样保留 WebP、稳定外链及下载/CORS。

图片资产不以图床 URL 作为身份。每个远端副本记录 `asset_id`、图床配置标识、远端对象标识、URL、状态和验证时间；凭据只在私有配置中，不能返回给前端或外部内容 agent。

切换默认图床只影响新增同步任务，已有副本继续可用。批量迁移时从本地 WebP 上传到新图床，逐批验证并切换活动副本，不重新生图或让客户端推测链接。对不支持幂等或查询的平台，上传超时且结果不明时进入待核对状态，不盲目重传。第一版图床未选定时后台显示“未配置”，资源 API 正常提供项目图片 URL，不能用测试链接声称 CDN 就绪。

## 6. 资源 API 与前端

前后端独立构建，通过同源 `/api/` 提供公开内容与鉴权管理接口。公开接口只读已激活内容，提供模特、穿搭、每日批次、过滤、搜索、排序和分页。图片字段返回 `image_url` 与 `source_url`：`source_url` 始终是项目图片的公开 URL，`image_url` 默认与其相同；只有 CDN 副本已验证可用时才返回对应 CDN 链接。不返回归档绝对路径、密钥或同步内部信息。

前端展示 `image_url`；CDN 图片加载失败时单次回退到 `source_url`，项目图片也失败则展示明确的图片不可用状态，不形成循环请求。普通图片与九宫格裁切使用同一资源选择规则，后备链接同样只允许清单中登记的公开资源，不把用户私有图片变成公开后备资源。

前端保留生动九宫格、单格、对比、收藏及详情导航，新增地区、模特和最新批次入口。移除造型写真版本切换及相关对照展示，避免残留详情、搜索、推荐或缓存重新引入 `v1`。移除“固定百套”的总数与容量假设，但保留稳定编号和旧收藏存储键；不能因列表分页未加载而清除收藏。

私人试穿按服务端登记的资产/模特展示/镜头选择本地参考，并在提交时冻结实际资源版本，不接收任意客户端 URL。历史任务保留原记录和资源引用，新任务只使用允许公开展示的生动版本。同步修改现有试穿和事件接口的 `le=100` 以及依赖固定 catalog 的处理。

图片跨域下载通过受控资源下载能力实现，不依赖旧的跨域 `download` 链接行为。离线浏览如继续保留，则导出活动内容快照及对应公开图片，不为在线运行保留第二个独立维护的 catalog。

## 7. 后台观察页面

- 访问分析：已有允许事件的趋势、来源于实际事件的地区或内容维度（仅限已明确采集的字段），不把估计填成事实。
- 用户穿搭观察：鉴权查看已有生成结果、任务状态与质量评估，继续禁止管理员读取自拍原图。
- 系统模特预览：基础体、多视角与对应生动穿搭，展示缺失资源和版本状态，不代替 Git 新增编辑内容。
- CDN 同步：当前接收版本、活动版本、图床配置状态、待处理/上传中/已验证/失败/待核对数量、字节数、错误与最近成功时间。仅在总量已知时由真实已验证数量计算进度。
- 运维操作：权限范围内重试失败同步、核对未知结果或切换资源副本；这些操作不触发生图或改写内容源。

## 9. 最新一期优先的展示与交付

首页使用最新批次封面，最近更新排除该套并最多展示六套；完整衣橱默认最新发布，分类、季节、模特与地区只筛选衣橱，不改变首页。模特封面来自真实归属的公开穿搭。详情有稳定 hash 地址，继续支持离线包、原收藏和九镜头。

批次可选 `published_at`（带时区且上海日期等于发布日期）与 `cover_look_id`（本批次内编号）。Node/Python 共用内容字段及发布规则，返回一致的 `revision`、`home` 和 `latestOrder`。历史批次省略时间时按上海发布日期零点排序，历史基线不补日期。前端不让不同版本的 API 覆盖构建快照。

显式交付工具先检查干净的已提交版本，暂存完整公开包，再切换静态目录并重启指定 API。交付后验证 API 与静态快照版本、首页主推编号、页面代码和主推 WebP 的实际哈希，私有发布记录只在成功后标记通过。后台分别显示已导入内容、网站交付验证与 CDN 同步。可选提交观察器只在授权环境中处理干净的新提交，失败不循环重启。失败回退静态包，不回退私有用户数据库；具体限制见[部署说明](../deploy/README.md)。

## 10. 专业 Agent 讨论与后续开发

2026-11-13 本轮由三类专业 agent 交叉审视现有内容、交互和代码：

| 角色 | 职责与交叉讨论结论 |
| --- | --- |
| 产品策略与浏览体验 | 检查首页到详情、筛选与返回路径。优先让已有标签成为明确的搜索入口，帮助用户从一套穿搭继续浏览；不把普通搜索包装成个性化推荐。 |
| 视觉内容与编辑 | 检查当前两套新图、九镜头与既有参考流程。利用已有镜头标题和景别帮助阅读及选择试穿参考；保留模特身份、九格裁切和完整鞋履镜头，不因界面改善重新生成图片。 |
| 系统架构与交付可靠性 | 核对内容版本、离线快照、上线回执与文档。体验改进使用已有字段和 hash 路由，不新增采集或后台内容来源；交付核验的覆盖缺口单独安排。 |

共同结论是先完成一个可验收的浏览闭环，再扩展发布可靠性与编辑表达。第一阶段为本轮实现范围，后续阶段为待办及验收约定；具体实现、回归和部署结果分别记录。

### 第一阶段：P1 首批体验改进（本轮开发范围）

- 详情页复用 `look.tags` 提供清晰的标签搜索入口，进入现有全部穿搭页并展示搜索条件；情绪说明不自动变成搜索词。查询通过 URL 编码保留中文及特殊字符，清除会意外限制结果的旧筛选。搜索只匹配自身时不声称存在其他相似穿搭。
- 复用现有 `shots` 的标题和景别，改善九镜头导览和试穿参考的可读性。保持镜头编号 1—9、完整九宫格视图 0、3×3 等分裁切和默认参考选择；不新增素材或自动猜选镜头，不暗示近景可以展示整套服装。
- 验收：在手机与桌面完成真实点击和键盘操作，镜头选中状态及说明同步，标题不引起横向溢出；分别从首页、带筛选的列表及收藏打开详情，执行标签搜索、浏览器后退和关闭详情，核对实际返回页面及筛选。刷新搜索链接仍能恢复条件。历史 100 套和新增两套均可使用，离线 `public/index.html` 可完成浏览，不依赖 API 或 CDN。首页始终保持最新批次封面，收藏编号与试穿镜头索引不变。
- 完成记录应分别列出源码与回归结果、推送/CI 结果和部署状态；本轮代码未经新的交付验收不得报告已上线。

### 第二阶段：发布核验与恢复

- 将现有封面核验扩展为明确的发布文件清单，覆盖核心静态文件（含样式和试穿脚本）、静态内容快照及最新批次的全部图片；管理站点单独核对版本和公开页面文件。保留 API/快照版本、主推编号、WebP MIME、字节数和哈希检查。
- 验收：正常候选可生成对应回执；任一核心文件过期、同批非封面图片缺失或哈希不符、API/静态版本不同都必须验收失败。模拟启动失败与切换后核验失败，确认旧静态包仍可恢复、回执明确失效、私有用户数据库不被回退；在授权环境交付时再核对真实 HTTPS。
- 网站交付回执继续表示其时间点的检查，CDN 状态独立，不作为持续健康监控。上述故障回归使用受控测试，不触发付费生图，不安装自动部署钩子。

### 第三阶段：编辑表达与内容多样性

- 从已记录的批次调研中设计简洁选题说明，明确来源日期、地区、天气适用日期和创作演绎范围；现有字段不足时先提出最小数据变更。无来源或已过适用日期的信息不表述为“今日热点”或实时天气，不补造历史日期、排行或热度。
- 对照相邻批次的九镜头标题、动作、表情、景别及微故事，发现重复后在下一次私有生成提示词中调整。仍逐套满足 SOP 的表情、动作、鞋履及互动要求，不通过改写元数据掩盖画面重复。
- 验收：选题说明可以追溯到真实链接与对应日期，缺失信息有明确省略或历史标记；下一次交付提交前实际检查图片，并记录跨批重复检查和已作调整。实际提示词与原始生成记录继续留在私有工作区。

### 第四阶段：免费图床候选调研与接入

- 另行查证候选平台的当前免费额度、原样 WebP、外链、上传/查询 API、删除或迁移能力及使用条款，形成可审阅比较后再决定接入；本轮不选定平台、不配置账户或密钥。
- 验收：真实接入须验证上传、远端字节和哈希、逐图切换、加载失败回源与更换平台；不支持原样保留或查询的能力限制必须说明。配置前后均保留项目图片 URL 与本地最终 WebP，不能因图床未就绪阻塞内容展示。
