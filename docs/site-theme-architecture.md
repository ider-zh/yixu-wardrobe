# 全站主题

管理员登录工作台后，在「网站主题」中选择并保存 Editorial 或 Studio。Editorial 延续留白叙事，Studio 以首页照片、较大的图库卡片、产品侧栏和后台导航侧栏为主。前台和已登录后台应用同一个部署的设置。

## 配置与读取

- `GET /api/site-theme` 只返回 `{"theme":"editorial"}` 或 `{"theme":"studio"}`，公开读取不需要会话。
- `GET /api/admin/site-theme` 读取同一设置，`PUT /api/admin/site-theme` 保存同样的 JSON。后台读取需要管理员会话，保存还需要现有的来源检查与 CSRF 令牌。
- 设置写入当前部署的私有 SQLite。已有数据库启动时自动补齐主题表，缺省为 Editorial。API 响应禁止缓存，设置独立于内容清单、图片发布版本和浏览器收藏。

前台打开页面、标签页重新可见或从浏览器缓存恢复时读取服务器设置。读取失败或返回未知值时保留当前布局。初次读取成功前以及直接打开离线包时使用 Editorial。旧浏览器主题存储、产品页 URL 预览参数和单品的 `presentation` 不参与选择。

## 布局 Module

`site-theme.js` 公开 `resolve()` 和 `subscribe(listener)`。后台入口额外使用 `apply(theme)`，在读取或确认保存后应用设置。两种布局只接受内置名称。后台保存失败时保留上次确认的显示，管理员可重新读取服务器设置。

两个 Adapter 按主题排列现有首页、图集、产品和工作台。前台保留路由、筛选、收藏、已选产品图和放大窗。试穿输入、Blob 预览、写真选择和排队任务保留原节点。后台导航和面板只在原本的鉴权容器内移动，退出或收到 401 时仍清空私有内容。

## 构建与验证

`site-resources.json` 声明前台和后台核心文件。构建、Node 发布验证和开发服务器控制器分别从候选版读取该清单，拒绝不合法的文件名和符号链接。`catalog.js` 由内容构建生成。后台从公开根目录加载主题脚本和样式，使用现有的同源 CSP。

回归覆盖匿名读取、管理员权限和 CSRF、重启持久化、分域兼容，以及真实 Chromium 中保存、访客重新读取、保存失败、退出和 401。测试使用合成数据验证 320、390、1440 像素布局、收藏与产品图集状态、试穿照片和排队节点及离线默认主题。
